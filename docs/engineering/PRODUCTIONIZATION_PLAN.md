# 成品化与运维方案

更新时间：2026-06-09

目标：让猪猪家的厨房可以长期部署在家用服务器上，供猪猪和猪宝稳定日常使用。重点不是“功能显得很多”，而是登录可靠、数据不丢、主要流程闭环、失败有提示、升级可回滚。

当前进度：第一版成品化目标已完成，按既定验收口径为 100%。后续进入真实日用后的体验微调、长期维护和周期性质检阶段。

## 阶段 1：安全与登录

状态：已完成。

- 签名 cookie。
- 同一设备保持登录。
- admin/member 权限。
- 未登录不可访问业务页。
- 业务 API 默认要求登录。
- 生产环境校验 `AUTH_SECRET` 和默认弱密码。

## 阶段 2：数据不丢

状态：已完成。

- Prisma 迁移已提交。
- 媒体上传落库。
- 原图备份、压缩、MIME 校验、大小限制和安全删除。
- Recipe 封面图持久化。
- CookLog 照片持久化。
- CookLog 删除会回滚 `cookCount`。
- 备份、备份验证和恢复演练脚本已落地。

## 阶段 3：日常闭环

状态：已完成。

- 计划周期按周二到下周一计算。
- 首页默认展示当前周真实计划。
- 没有当前周计划时显示未规划状态；计划页支持左右箭头切换历史周和未来周。
- 计划页支持左右箭头切换上/下周，过去周可编辑并显示"已过去"标识。
- 每天可标记"不安排"，AI 推荐和购物清单自动跳过已标记天。
- 周计划保存、复制、归档、重新生成。
- 购物清单从周计划生成。
- 勾选、家里已有、临时项刷新不丢。
- 做饭模式完成后生成 CookLog。

## 阶段 4：推荐、回顾与 PWA

状态：已完成。

- 推荐服务统一首页、周计划和冰箱清理推荐。
- 推荐理由已返回。
- 成就模型和事件服务已落地。
- PWA manifest、图标、离线页和基础缓存已落地。

## 阶段 5：工程与发布

状态：已完成。

- `npm run check:mojibake`
- `npm run lint`
- `npm run typecheck`
- `npm run test`
- `npm run test:e2e`
- `npm run build`
- `npm run backup`
- `npm run verify:backup`
- `npm run restore:drill`
- `npm run export:docker-data`
- `npm run docker:smoke`

E2E 使用独立测试库和端口，不再污染日常开发数据。

Docker 迁移包已按当前数据导出到 `docker-data/`，manifest 会记录并校验所有业务表行数、上传目录文件数和媒体引用缺失情况。当前本机已通过数据级 `docker:smoke`；Compose 运行态 smoke 需要在装有 Docker CLI 的目标机器继续执行。

## 后续维护方向

1. 每次发布前重跑完整质量门。
2. 定期做恢复演练。
3. 用真实手机检查购物、做饭、打卡和海报体验。
4. 持续清理用户页面里的开发说明、硬术语和没有生活感的文案。
5. 根据真实使用反馈调整首页、计划、购物和做饭模式的优先级。
