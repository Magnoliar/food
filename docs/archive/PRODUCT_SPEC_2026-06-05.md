## 一、项目定位

### 初始需求
个人菜谱规划、记录、存档、发布系统。用户 momo 和恋人使用，替代笔记工具手动记录周菜单的模式。

### 需求本质挖掘
不仅是菜谱记录工具，而是一个**家庭烹饪操作系统** —— 涵盖"想吃什么→怎么买→怎么做→做了怎么样→下次怎么改进"的完整闭环。核心价值在于：让烹饪从"每天要想"变成"周二规划一次，一周执行"。

### 实现逻辑
数据驱动的状态机：首页根据当前时间+计划数据自动切换 6 种状态，用户不需要主动导航，打开就知道该做什么。

### 实现方法
Nuxt 3 全栈 + Prisma SQLite + Tailwind CSS + D3.js

## 二、烹饪逻辑

### 初始需求
工作日每天晚上做晚餐+次日便当，周末午餐+晚餐，周五不带便当，同一道菜可吃两天。

### 需求本质挖掘
不是简单的"每天选两道菜"，而是一个**时间感知的备餐系统**：今晚做的决定明天中午吃什么，明天中午的食材今晚就要准备。系统需要理解"今晚任务"的实际范围。

### 实现逻辑
- `meal1` = 第一顿（工作日=晚餐，周末=午餐）
- `meal2` = 第二顿（工作日=次日便当，周末=晚餐）
- 同一道菜检测：`meal1.recipeId === meal2.recipeId` → 提示"多做一份"
- 提前准备：关键词匹配（肉/鸡/鸭/鱼/虾/牛/猪/排骨）明天晚餐的食材
- 首页合并展示：晚餐+便当的食材去重合并

### 完成度：**95%**
6 种状态全部实现（未规划/已规划未做/已做未记录/已记录/周五/周末），接入真实数据。

### 功能完备性：9/10
- 同一道菜检测 ✅
- 提前准备食材 ✅
- 合并食材清单 ✅
- 周五特殊卡片 ✅
- 周末回顾统计 ✅
- 烹饪状态接入真实 cook-log API ✅

### 鲁棒性：8/10

- 状态从真实 cook-log API 获取 ✅

### 展望

## 三、设计系统

### 初始需求
杂志风格，留白居多，法式风格，食材手绘速写线稿，莫兰迪/大地配色，PMA响应式。

### 需求本质挖掘
用户要的不是"好看"，而是**有温度的数字厨房** —— 像翻开一本料理杂志，而不是看一个数据表格。设计需要传递"烹饪是享受"的情感。

### 实现方法
- 配色：莫兰迪 14 色 + 蜡笔色 8 色 + 赤陶红强调色
- 字体：Noto Serif SC（标题）+ Noto Sans SC（正文）+ Caveat（手写）+ JetBrains Mono（数据）
- 质感：毛玻璃卡片 `blur(8px)` + 白底 + 极柔阴影
- 动画：fade-in 页面过渡 + 卡片 hover 上浮 2px + 贴士自动轮播
