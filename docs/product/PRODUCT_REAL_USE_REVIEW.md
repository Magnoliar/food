# 真实使用复盘

更新时间：2026-06-09

这份文档面向后续开发者和产品决策。它不要求一次性全部实现，而是把“家里真的每天用”时最容易卡住的地方拆成可执行改造点。前端页面显示的文字仍应保持日常、人情味，避免把开发、部署这类表达露给使用者。

## 总体判断

猪猪家的厨房的主链路已经清楚：计划一周吃什么，生成购物清单，照着菜谱做饭，做完记录，再按需要生成打卡卡片。当前真实使用风险主要不在“有没有功能”，而在功能之间的路径成本、移动端信息优先级、重复控件和空状态文案。

最应该优先解决的痛点：
- 首页要更像今天的厨房台面，少一点概览感，多一点下一步。
- 计划和购物要顺着真实节奏走：周二开始、下周一结束，部分格子手填后 AI 只补空位。
- 移动端食材页必须能看清库存状态，买菜时比线稿和分类更重要。
- 记录和打卡要打通缺信息回补路径，减少“想留念但发现资料不全”的挫败感。
- 增强功能不要抢主流程位置，图谱、旅程、成就更适合安静地放在二级频率。

## 首页

PM 判断：
- 首页应该回答“今天吃什么、现在该做什么、还有什么没准备好”。
- 推荐和统计可以存在，但不应压过今日计划、开始做饭、待记录和购物缺口。

真实痛点：
- 晚饭前打开首页，如果第一眼看到的是推荐或概览，用户还要再判断下一步。
- 本周未规划、今日无菜、已做但未记录，这三种状态需要清楚分开。

建议改造：
- 首屏固定为今日状态卡：今日菜、开始做饭、查看菜谱、记录今日。
- 如果今日未规划，主按钮去计划页；如果已完成做饭但没记录，主按钮去记录。
- 增加购物缺口提示：来自当前周计划但购物清单未完成的关键项。

验收标准：
- 5 秒内能判断今晚吃什么或该去哪里补计划。
- 首页不出现 Demo、测试、账号配置、部署说明。
- 今日状态变化后刷新不回到旧计划或静态数据。

## 计划与购物

PM 判断：
- 计划页是晚饭决策和采购准备的入口，不是菜谱展示页。
- AI 补空位必须尊重手填内容，不能覆盖“已经想做的几道菜”。

真实痛点：
- 家里购物和计划从周二到下周一，默认自然周会打断真实节奏。
- 周五不需要准备次日便当，这类提示如果写得太硬，会显得像排班系统。
- 购物清单应该和计划待在一起；拆成单独页面会让排菜和买菜来回跳。

建议改造：
- 固定支持周二到下周一的计划周期，并在 UI 上用更日常的文案表达。
- AI 补空位只填空槽，手动填写的菜保持不动；补全前后给出温和反馈。
- 购物清单保留在计划页内，移动端提升优先级：未完成项优先、分类可折叠、勾选刷新不丢。
- 周末顺序按午餐再晚餐展示，符合真实安排。
- 支持左右箭头切换上/下周，查看历史或预填未来计划。
- 每天可标记"不安排"（外出就餐/旅游/放假/自定义），AI 补位和购物清单自动跳过。

验收标准：
- 手填 2-3 道菜后 AI 补全不会覆盖。
- 生成购物清单后重新生成不丢勾选和手动项。
- 手机上购物勾选单手可用，库存标记清楚。
- 手机上计划表不能横向溢出。
- 切换上/下周能正确加载对应计划，过去周显示"已过去"标识。
- 标记"不安排"后 AI 推荐不会填充该天，购物清单不含该天食材。

## 菜谱

PM 判断：
- 菜谱库的第一任务是找菜和改菜，不是展示数据成绩。
- 从打卡页、记录页、计划页跳回菜谱时，要能直接定位到要补的信息。

真实痛点：
- 搜索、筛选、新建和随机如果被统计卡片压住，找菜效率下降。
- 缺封面、缺步骤、缺食材时，用户不想从详情页重新找编辑位置。

建议改造：
- 搜索栏、新建、随机一道保持高优先级。
- 详情页继续支持 `?edit=cover|ingredients|steps`，并让对应区域有明确编辑态。
- 菜谱卡片优先显示真实封面；没有封面时用稳定占位，不用食材图冒充成品。

验收标准：
- 从打卡页“补成品照/补食材/补步骤”能直接进入对应编辑位置。
- 移动端搜索和新增不被折叠到难找的位置。
- 图片加载失败不会破图或导致布局跳动。

## 食材与库存

PM 判断：
- 食材页有探索价值，但真实买菜时库存状态更重要。
- 移动端应先服务“家里还有什么”，再服务“这个食材长什么样、属于哪类”。

真实痛点：
- 手机界面如果看不到冷藏、冷冻、常温状态，买菜时就失去核心价值。
- 线稿生成、分类、详情抽屉过重时，会遮住库存这个高频需求。

建议改造：
- 移动端顶部增加库存摘要：冷藏、冷冻、常温三个入口或横向卡片。
- 食材列表卡片显示库存状态的小标签，能快速标记“家里有/要买/用完”。
- 线稿相关操作收进详情或管理区，不抢移动端首屏。

验收标准：
- 手机打开食材页第一屏能看到库存状态入口。
- 搜索某食材时能同时知道它是否在家里。
- 库存增删保存后刷新仍保持。

## 做饭模式

PM 判断：
- 做饭模式是厨房现场页面，要低干扰、大字号、可远距离看。
- 完成后应自然进入记录，而不是让用户自己想下一步。

真实痛点：
- 手上有水时，小按钮、复杂弹窗、页面滚动都很烦。
- 步骤长时如果字号小或布局抖动，手机架在厨房台面上很难看。

建议改造：
- 保持全屏步骤、进度、倒计时、完成按钮的优先级。
- 完成后提供轻记录入口：评分、照片、备注可分步补。
- 动画只用于步骤切换和完成反馈，避免大幅位移。

验收标准：
- 手机无需放大即可读步骤。
- 完成做饭会创建或引导创建记录。
- 离开再回来不丢当前步骤进度。

## 记录与打卡

PM 判断：
- 记录是事实留存，打卡是把一次饭做成可分享的留念。
- 打卡页不能像运营工具，应该短、轻、像一次饭后的留念。

真实痛点：
- 做完饭后如果还要填很多表，用户会放弃记录。
- 打卡时发现缺照片、评分、复盘、步骤，如果不能快速补，会中断兴致。
- 打卡页切换方式太多会显得重复，右侧文字模板按钮已经不必要。

建议改造：
- 打卡页保留左右箭头、移动滑动和下方点点；删除右侧“卡片”文字选择。
- 保留“补齐这张卡”入口，按缺失项跳到菜谱或记录编辑。
- 记录弹窗区分“快速记录”和“补完整”，允许先保存基础记录。

验收标准：
- 打卡页右侧只保留菜谱、做饭记录、比例、导出。
- 点点、箭头、移动滑动都能切换模板。
- 导出 PNG 不包含选择器、按钮、编辑入口。

## 图谱、旅程、成就、管理

PM 判断：
- 这些是增强层和维护层，不应挤占计划、购物、做饭、记录。
- 它们可以增加情绪价值，但不能要求用户每天都处理。

真实痛点：
- 导航入口过多时，用户会分不清哪些是日常必须做。
- 成就如果太像任务榜，会让家用工具变得有压力。

建议改造：
- 桌面侧栏保留完整入口，移动端只保留最高频任务。
- 移动端底栏固定为：首页、计划、菜谱、食材、打卡。
- 旅程偏复盘，成就偏轻鼓励，图谱偏探索，管理只给 admin。
- 文案避免“系统、正式态、运营、配置”等硬词出现在普通页面。

验收标准：
- 移动底栏不超过 5 个高频入口。
- 普通用户不看到管理入口。
- 增强页不会干扰主流程完成。

## 2026-06-09 本轮落地

- 首页改为真实 API 数据驱动，不再依赖 `useMockData()` 的静态周计划；今日日期按本地日期计算，避免跨时区导致首页状态跑偏。
- 首页购物缺口入口指向计划页，购物清单继续和周计划合并。
- 购物清单分类支持折叠，未买项优先显示，勾选和“家里有”触控面积加大；进度统计把“家里有”也视为已处理。
- 移动端底栏恢复为：首页、计划、菜谱、食材、打卡。
- 计划页移动端保留小卡片气质，同时避免横向溢出、右侧大块空白和日期夹在两个餐位之间。
- 前端清理了一批说明式备注，用户侧文案改为更短的状态和动作。
- 做饭模式会在同一设备保存当前步骤和随手备注；离开后再回来不丢进度。
- 做饭完成后直接创建记录并跳到记录编辑弹窗，照片、评分和复盘可以顺手补完整。
- Docker 迁移路径补齐：启动自动迁移，正式 compose 直接挂载 `docker-data`，导出包包含 manifest，新增 `npm run export:docker-data` 和 `npm run docker:smoke`。

## 2026-06-10 本轮落地

### AI 集成

- 推荐系统加 LLM 层：规则打分后用 light 模型生成温馨推荐理由，可选开启（`enrichWithAI`）。
- 做饭模式每步显示 AI 智能提示（火候、时间、常见翻车点），后台加载不阻塞操作。
- 做饭记录弹窗新增"AI 帮写"按钮，根据评分和评语自动生成复盘草稿。
- 菜谱详情食材悬停"?"获取 AI 替代建议（替代品 + 用量调整）。
- 周计划 AI 填充升级为智能编排，考虑荤素搭配、口味多样性、烹饪方式交替。
- 首页后台加载个性化 AI 今日贴士（基于最近做的菜、冰箱、季节）。
- 食材详情页新增"AI 解读"，显示常见搭配、存储技巧、时令状态。
- 购物清单生成时对比冰箱库存，已有食材自动标记 inStock。

### AI 鲁棒性

- aiChat 加 30s 超时（AbortSignal.timeout），防止上游挂死。
- JSON 解析失败抛 422 错误，不再静默返回 `{ raw }`。
- AI 菜谱输出用 parseRecipePatch 做 schema 校验。
- temperature、maxTokens、timeoutMs 可按调用覆盖。
- auto-tag 批量调用加 500ms 间隔防速率限制。
- XYQ prompt 集中管理为 `lineArtPrompt()` 函数。

### UX 改进

- 首页推荐区域独立后台加载，不阻塞页面渲染。
- 计划页"保存计划"和"生成购物清单"合并为一个按钮"保存并同步清单"。
- 计划页输入实时保存（800ms 防抖），无需手动点按钮。
- 计划页未完成输入自动匹配第一个菜谱，避免新建乱七八糟的记录。
- 打卡页菜谱选择从 `<select>` 改为可搜索输入框。
- 菜谱详情食材新增支持自动联想已有食材数据库。
- 首页"补一下菜谱"跳转到新建菜谱页并预填菜名。
- 全站文案从机械直述改为日常温暖风格（空状态、加载状态、反馈消息）。
